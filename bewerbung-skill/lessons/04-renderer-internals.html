1. tr() — der Übersetzungsfilter

def tr(value, lang):
    if isinstance(value, dict) and ("de" in value or "en" in value):
        return value.get(lang, value.get("de", ""))
    return value

Drei Verhaltensweisen in vier Zeilen:

Eingabe--lang en liefert
{de: "Hallo", en: "Hi"}Hi
{de: "Hallo"} (kein en)Hallo ← stiller Fallback
"Python · Git" (kein Dict)Python · Git unverändert durchgereicht
Warum der Passthrough clever ist: Du musst nicht jedes Feld zweisprachig anlegen. name, tech, chips, URLs bleiben einfache Strings, und |tr im Template stört nicht. Nur wo du wirklich übersetzt, machst du ein Dict daraus.
Der Preis: Ein Tippfehler im Key — {de: …, eng: …} — ist syntaktisch gültiges YAML und ein gültiges Dict. tr() findet kein en, nimmt de, und dein englischer CV ist an der Stelle deutsch. Kein Fehler, keine Warnung. Deshalb: englisches PDF nach jedem Setup einmal komplett durchlesen.

Wie der Filter ins Template kommt

env.filters["tr"] = lambda v: tr(v, ctx["lang"])

Die Sprache steckt per Closure im Filter — deshalb schreibt das Template nur {{ d.rolle|tr }} und muss die Sprache nie durchreichen. Ein Render-Aufruf = eine Sprache; für zwei Sprachen läuft das Script zweimal.

2. autoescape=True

env = Environment(loader=FileSystemLoader(TEMPLATES), autoescape=True)

Jeder Wert aus deinem YAML wird HTML-escaped, bevor er im Template landet.

Du schreibst in master.mdIm PDF steht
C&AC&A ✅ (intern &amp;)
<b>Unity</b>wörtlich <b>Unity</b>, nicht fett
Warum das richtig so ist: Ein Anschreiben-Body kann Text aus einer gescrapten Anzeige enthalten (Lektion 10). Ohne Autoescape wäre eine Stellenanzeige mit HTML darin in der Lage, dein Layout zu zerlegen. Der Preis: Du kannst Text nicht per HTML formatieren. Formatierung gehört ins CSS, nicht in die Daten.

3. paragraphs() — die Absatzregel

def paragraphs(body):
    return [p.strip() for p in re.split(r"\n\s*\n", body) if p.strip()]

Split an Leerzeile. Jeder Block wird ein <p>. Ein einzelner Zeilenumbruch trennt nicht — der Text landet im selben Absatz und wird vom Browser umgebrochen wie normaler Fließtext.

# zwei Absätze
Sehr geehrte Damen und Herren-Text.

Zweiter Absatz.

# EIN Absatz (einfacher Umbruch zählt nicht)
Sehr geehrte Damen und Herren-Text.
Zweiter Absatz.

4. html_to_pdf() — der Chrome-Aufruf

cmd = ["google-chrome", "--headless=new", "--no-sandbox", "--disable-gpu",
       "--no-pdf-header-footer", f"--print-to-pdf={out_pdf}", f"file://{tmp}"]
FlagWarum
--headless=newder aktuelle Headless-Modus; der alte konnte kein sauberes print-to-pdf
--no-sandboxnötig als root auf dem Server. Auf einem Desktop-Account wäre es unnötig.
--no-pdf-header-footerohne das druckt Chrome Dateiname, URL, Datum und Seitenzahl in die Ränder — auf einem CV ein Killer
file://{tmp}der Tempfile mit dem gerenderten HTML; wird danach mit unlink(missing_ok=True) entfernt
Warum das HTML in einen Tempfile muss: Chrome braucht eine URL, keinen String. Und weil der Tempfile irgendwo in /tmp liegt, würde <link href="cv.css"> ins Leere zeigen. Deshalb setzt jedes Template <base href="{{ base }}"> mit TEMPLATES.as_uri() + "/" — damit CSS und Fonts relativ zum templates/-Ordner aufgelöst werden. Nimm das <base> raus und du bekommst ein ungestyltes PDF.

Timeout: 60 Sekunden. Erfolgsprüfung: returncode == 0 und die Datei existiert — beides, weil Chrome gelegentlich mit 0 endet, ohne geschrieben zu haben.

5. Was bei fehlendem Feld passiert

Jinja2 läuft hier im Default-Modus (kein StrictUndefined). Das heißt:

  • {{ d.telefon }} bei fehlendem Key → leerer String, kein Fehler.
  • {% for p in d.projekte %} bei fehlendem projekte → UndefinedError: '…' is undefined, weil über Undefined nicht iteriert werden kann.

Praktisch: Fehlende Skalare verschwinden lautlos, fehlende Listen krachen. Zweite gute Nachricht, erste schlechte.

Do it (Experiment, danach zurücksetzen):
  1. Schreib in master.md testweise rolle: {de: Games Programmer, eng: Games Dev}, rendere --lang en. Ergebnis: „Games Programmer". Das ist der stille Fallback, live gesehen.
  2. Setz probeweise tech: "<b>Unity</b> · C#" und rendere. Die Tags stehen wörtlich im PDF — Autoescape in Aktion.
  3. Beides zurücksetzen.

Check

1. tech: "Python · Git" ist kein Dict. Was macht {{ p.tech|tr }}?
  • Gibt den String unverändert zurück — tr() greift nur bei Dicts mit de/en
  • Wirft einen TypeError
  • Gibt einen leeren String zurück
2. Du löschst <base href="{{ base }}"> aus cv.html.j2. Folge?
  • Chrome bricht mit Exit-Code 1 ab
  • Das PDF entsteht, aber ohne CSS und Fonts — die relativen Pfade werden gegen /tmp aufgelöst
  • Nichts, base ist nur Doku
3. Im Anschreiben stehen zwei Sätze untereinander ohne Leerzeile dazwischen. Wie viele <p> entstehen?
  • Eines — paragraphs() splittet nur an Leerzeilen
  • Zwei — jeder Zeilenumbruch ist ein Absatz
  • Keines, der Body wird verworfen

Gelernt

  • tr(): Dict mit de/en → Sprache wählen, sonst Passthrough; fehlendes en fällt still auf de.
  • autoescape=True: HTML in Daten wird wörtlich gedruckt — Schutz gegen fremden Anzeigentext, Preis: keine Inline-Formatierung.
  • paragraphs(): Leerzeile = neuer Absatz, einfacher Umbruch nicht.
  • Chrome-Flags: --headless=new, --no-sandbox, --no-pdf-header-footer; Erfolg = Exit 0 und Datei existiert.
  • <base href> ist die Brücke vom Tempfile zu CSS/Fonts — nicht entfernen.
  • Fehlender Skalar → leer; fehlende Liste → UndefinedError.
