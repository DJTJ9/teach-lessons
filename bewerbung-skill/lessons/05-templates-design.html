Lektion 5 von 10 · Das Layout ändern, ohne blind zu raten — und die 296mm-Falle

Die wichtigste Zeile im ganzen Repo

/* cv.css */
@page { size: A4; margin: 0; }
body {
  width: 210mm; height: 296mm; overflow: hidden;
  padding: 12mm 14mm;
}
Die 296mm-Falle: Der CV ist hart einseitig. Was nicht auf die Seite passt, wird von overflow: hidden abgeschnitten — ohne Fehler, ohne Warnung, ohne zweite Seite. Der Render meldet Erfolg, das PDF sieht auf den ersten Blick normal aus, und dein letzter Job fehlt einfach.

Deshalb gilt nach jeder inhaltlichen Erweiterung von master.md: PDF öffnen und bis zum Seitenende scrollen. Steht unten „Ausbildung" und „Links", ist alles drin. Endet die Seite mitten in einem Listenpunkt, hast du Verlust.
Warum 296 und nicht 297? A4 ist 297mm hoch. Bei exakt 297mm reicht ein Rundungsfehler von Chrome, und der Inhalt rutscht auf eine zweite, fast leere Seite. 1mm Puffer verhindert die Geisterseite. Der Preis ist die harte Kante.

Das CV-Layout in drei Blöcken

header    Name · Rolle · Spielerpfad · Kontaktzeile, Trennlinie unten
main      grid-template-columns: 1fr 56mm
 ├─ .haupt   Profil · Projekte · Erfahrung
 └─ aside    Skills · Sprachen · Ausbildung · Links (56mm fest)

Zweispaltig per CSS-Grid mit fester Seitenspalte. Willst du die Seitenspalte breiter, änderst du 56mm — die Hauptspalte (1fr) gibt automatisch nach.

Der h-Block ist ein Mini-Wörterbuch im Template: 
{% set h = {
  'profil': {'de': 'Profil', 'en': 'Profile'},
  'projekte': {'de': 'Projekte', 'en': 'Projects'}, …
} %}
Aufgerufen als {{ h.profil|tr }} — dieselbe {de:,en:}-Mechanik wie bei den Daten, nur für feste Beschriftungen. Deshalb stehen Überschriften nicht in master.md: sie sind Layout, nicht Inhalt.

Design-Iteration: der Loop

render.py löscht sein Zwischen-HTML sofort wieder (Path(tmp).unlink()). Zum Anschauen im Browser erzeugst du es selbst — render.py ist importierbar, weil alles hinter if __name__ == "__main__" steht:

cd /root/projekte/bewerbung && python3 -c "
import sys; sys.path.insert(0,'scripts')
from render import load_front_matter, render_html, TEMPLATES
d,_ = load_front_matter('profil/master.md')
html = render_html('cv.html.j2', {'d': d, 'lang': 'de', 'base': TEMPLATES.as_uri()+'/'})
open('/tmp/cv-de.html','w').write(html)
print('/tmp/cv-de.html')
"

Diese Datei öffnest du im Browser bzw. lässt sie per chrome-devtools-MCP laden (headless + --no-sandbox). Dann: CSS im DevTools live tweaken → funktionierenden Wert nach templates/cv.css übertragen → render.py cv → PDF gegenprüfen.

Browser ≠ PDF. Am Bildschirm gibt es kein @page, kein Paginieren und keinen Print-Farbraum. Das HTML ist gut genug für Abstände, Farben und Grid — der finale Umbruch entscheidet sich erst im PDF. Nie eine Layout-Änderung nur im Browser abnehmen.

Die Schriften

templates/fonts.css      @font-face-Definitionen
templates/fonts/
  space-grotesk-600/700.woff2   Headlines: h1, h2, .rolle
  ibm-plex-sans-400/600.woff2   Fließtext
  ibm-plex-mono-400.woff2       .mono — Kontakt, Zeiträume, Chips, Links

Alle lokal, geladen über @import "fonts.css" und das <base href>. Neue Schrift = .woff2 nach templates/fonts/ + @font-face in fonts.css + Nutzung in cv.css. Kein CDN-Link — sonst hängt dein PDF-Aussehen an einer Internetverbindung.

Nach jedem Template-Eingriff

python3 -m pytest scripts/test_render.py -q

Das ist genau der Fall, für den der Test da ist: Er rendert mit einer eigenen Fixture und stellt fest, ob deine Template-Änderung die Pipeline zerlegt hat (z.B. Tippfehler im Jinja-Tag, fehlendes {% endfor %}).

Do it:
  1. HTML mit dem Snippet oben dumpen und im Browser öffnen.
  2. Provozier die Falle: Häng in master.md testweise 6 weitere erfahrung-Einträge an, rendere, schau ins PDF. Beobachte, dass unten Inhalt fehlt — und dass das Script trotzdem Erfolg meldet. Danach zurücksetzen.
  3. Ändere in cv.css 1fr 56mm auf 1fr 62mm, rendere, vergleiche. Behalte den Wert, der dir besser gefällt.
  4. pytest laufen lassen.

Check

1. Dein CV hat einen Job zu viel. Was zeigt render.py an?
  • „Inhalt passt nicht auf eine Seite"
  • Es entsteht eine zweite PDF-Seite
  • Nichts — Erfolgsmeldung wie immer, der Überhang wird von overflow: hidden stillschweigend abgeschnitten
2. Du willst die Überschrift „Erfahrung" in „Werdegang" ändern. Wo?
  • In master.md, neues Feld ueberschriften:
  • Im {% set h = {…} %}-Block in cv.html.j2 — und dort gleich DE und EN
  • In cv.css über content:
3. Warum reicht es nicht, das gedumpte HTML im Browser abzunehmen?
  • Der Browser kennt @page und die 296mm-Grenze nicht so wie der PDF-Druck — der echte Beschnitt zeigt sich erst im PDF
  • Weil das HTML ohne CSS gerendert wird
  • Weil der Browser die lokalen Fonts nicht laden kann

Gelernt

  • body { height: 296mm; overflow: hidden } ⇒ CV ist hart einseitig, Überhang wird still abgeschnitten. Immer ins PDF schauen.
  • Layout = header + Grid 1fr 56mm (Hauptspalte / Seitenspalte).
  • Beschriftungen leben im {% set h %}-Block des Templates, nicht in den Daten.
  • HTML zum Debuggen selbst dumpen (render.py ist importierbar), im Browser tweaken, in cv.css übernehmen, im PDF gegenprüfen.
  • Fonts liegen lokal als .woff2 — kein CDN.
  • Nach jedem Template-Eingriff pytest scripts/test_render.py.
