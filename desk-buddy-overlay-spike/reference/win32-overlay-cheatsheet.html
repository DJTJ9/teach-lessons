4 · Init-Reihenfolge

if (Application.isEditor) return;                 // 0. Editor schützen (sonst zerlegst du den Editor)
hwnd = GetActiveWindow();                          // 1. Handle + Null-Prüfung mit Log
SetWindowLongPtr(hwnd, GWL_STYLE, WS_POPUP|WS_VISIBLE);
SetWindowPos(hwnd, 0,0,0,0,0, NOMOVE|NOSIZE|NOACTIVATE|FRAMECHANGED);  // 2. randlos
DwmExtendFrameIntoClientArea(hwnd, MARGINS(-1,-1,-1,-1));              // 3. Sheet of Glass
SetWindowLongPtr(hwnd, GWL_EXSTYLE, WS_EX_LAYERED|WS_EX_TOOLWINDOW);   // 4. layered, click-through AUS
SetLayeredWindowAttributes(hwnd, 0, 255, LWA_ALPHA);                   // 5. Fenster-Alpha voll
SetWindowPos(hwnd, HWND_TOPMOST, 0,0,0,0, NOMOVE|NOSIZE|NOACTIVATE);   // 6. nach oben
// + alle 5 s Schritt 6 wiederholen (Vollbild-Spiele/UAC werfen dich raus)

5 · Hit-Test pro Frame

GetCursorPos(out p);                    // NIE Input.mousePosition — friert unter WS_EX_TRANSPARENT ein
localX = p.X - windowLeft;
localY = windowHeight - (p.Y - windowTop);  // Win32 Y↓ → Unity Y↑
world  = camera.ScreenToWorldPoint(new Vector3(localX, localY, 0));
overOwn = Physics2D.OverlapPoint(world) != null;   // Punkt-Test, kein Raycast

desired = !(overOwn || dragLock);           // DragLock = Veto
if (!initialized || desired != last) { last = desired; ApplyExStyle(desired); }  // nur bei Kantenwechsel

6 · Drag

OnMouseDown : cursorStart = GetCursorPos(); windowStart = Position; dragLock = true;
Update      : if (!Input.GetMouseButton(0)) { dragLock = false; Save(Position); return; }
              Position = windowStart + (GetCursorPos() - cursorStart);   // absolut, nicht inkrementell
Drag-Ende nie über OnMouseUp — das feuert nur, wenn der Cursor beim Loslassen noch über dem Collider steht. Beim schnellen Ziehen bliebe der DragLock sonst für immer an.

SymptomWahrscheinlichste Ursache
Schwarze/graue Box statt TransparenzD3D12 aktiv oder Flip-Model an → Settings prüfen. Danach testweise SetLayeredWindowAttributes weglassen (reine DWM-Variante).
Click-through schaltet einmal an und nie wieder ausIrgendwo doch Input.mousePosition statt GetCursorPos.

Fenster verschwindet hinter anderenRe-Assert-Timer läuft nicht (InvokeRepeating in Awake).
Rahmen weg, aber Inhalt verschobenSWP_FRAMECHANGED fehlt nach dem Style-Wechsel.
Hit-Test trifft danebenY-Achse nicht gespiegelt oder GetWindowRect-Ursprung nicht abgezogen. (Bei DPI ≠ 100 %: Skalierungsfaktor fehlt — im Spike ungelöst.)
App nicht beendbarWS_EX_TOOLWINDOW ohne eigenen Beenden-Weg → Rechtsklick/Tray/Hotkey nachrüsten.
Speicher-Messwert konstant 0Process.WorkingSet64 unter Mono → psapi!GetProcessMemoryInfo.
Editor verliert Titelleiste / verhält sich seltsamApplication.isEditor-Ausstieg fehlt — GetActiveWindow traf das Editor-Fenster.

8 · Architektur-Regeln

  • Genau eine Datei mit DllImport — auch für nachträgliche Fixes.
  • Kein IntPtr in der öffentlichen Fassade; Vokabular ist Position, ClientSize, SetClickThrough.
  • Fassade no-oppt im Editor; IsActive == false lässt alle Aufrufer sauber aussteigen.
  • Native Aufrufe nur bei Zustandswechsel, nicht pro Frame.
  • Zentrale Verdrahtung im Bootstrap (Execution Order −100), kein Singleton/FindObjectOfType.
  • Testschnitt: nur reine Logik testen (Zustandsautomat, Persistenz) — DllImport-Wrapper nicht mocken.
  • Sichtbeweis bleibt manuell: Fenster dahinter, danebenklicken, draufklicken, schnell ziehen, neu starten, Vollbild-Spiel dazwischen.
Automatisierte Vollbild-Screenshots auf einem echten Arbeitsrechner: nicht. Sie erfassen Browser-Tabs, Chats und ggf. Zugangsdaten. Nur gezielt das Zielfenster aufnehmen — oder den Menschen fragen.
